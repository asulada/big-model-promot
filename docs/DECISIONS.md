# 重大修改记录

只记录重大修改或重要结论，小修（typo、格式、局部重构、调试）不记。

**本文件只放写入规则与索引。** 正文按月归档在 [`docs/decisions/`](decisions/)，需要细节时按索引点进去读，不要整读归档。

## 写入规则

**什么算重大**（其余一律不记）：

- 改变后续开发方向的结论（如证伪根因假设）
- 改对外行为、公共接口、数据格式
- 新增/弃用核心机制或依赖
- 推翻旧结论

**格式**：`## YYYY-MM-DD · 一句话结论`，下接三段：**背景**（现象与缘由）、**决定**（做法与取舍）、**影响**（下游改动、限制）。

**硬性上限**（超了说明还没提炼完）：

- 单条 ≤ 1,200 字 / ≤ 25 行
- 背景 ≤ 3 句，决定 ≤ 3 条，影响 ≤ 3 条
- 不写实测数据表、代码块、文件行号；要留证据就引用提交号或归档路径

**待办不进这里**：未完成事项写进 `docs/测试和记录文档/遗留问题清单-YYYYMMDD.md`。

**同主题**：更正、补充用 `### 更正（同日）` 或 `### 补充（同日）` 挂在最近一条下方，不新开 `##`。

**出栈**：被推翻的条目，正文整块移到 [`docs/decisions/archive.md`](decisions/archive.md)（没有就新建），索引行改成「~~已取代~~ → archive」。搬移不算改写，原文字一句不动。

**落盘流程**：新条目追加到当月归档文件末尾 → 在本文对应月份的索引里加一行 → 跨月时新建 `docs/decisions/YYYY-MM.md`。

**读取方式**：先 `grep -n '^## ' docs/decisions/YYYY-MM.md` 拿目录，命中再读那一段。索引里的结论行足够回答「有没有做过 / 当时怎么定的」时，不要展开正文。
