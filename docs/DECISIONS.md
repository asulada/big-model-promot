- # 重大修改记录

  只记重大修改与重要结论。小修（typo、格式、局部重构、调试）不记。

  本文件只放规则。决策正文在 `decisions/YYYY-MM.md`（索引 `decisions/index/YYYY-MM.index.md`，被推翻的移入 [archive.md](decisions/archive.md)）；现状在按主题拆开的 [current/](current/)；实验证据在 `docs/测试存档文件/<日期>-<主题>/`。

  ## 什么算重大

  - 改变后续开发方向的结论（含证伪）
  - 改对外行为、公共接口、数据格式
  - 新增/弃用核心机制或依赖
  - 推翻旧结论

  只改现状、不产生新结论的，不动 `decisions/`（不写正文、不加索引行），只覆盖 `current/` 对应页。

  ## 每条怎么写

  标题 `## YYYY-MM-DD · 一句话结论`，正文三段：**背景** ≤3 句 / **决定** ≤3 条 / **影响** ≤3 条。
  硬帽 ≤1200 字、≤25 行；不写表格、代码块、文件行号。
  出现任何实测量，正文只留一行数字，后接 `证据：docs/测试存档文件/<日期>-<主题>/`。
  暂未验证的结论照常写，正文首行挂 `> 🧪 待验证：<验证条件>`；验证后按下面的更正/推翻规则处理。
  不另设草稿文件或流水日志——「判不准归类」时先覆盖 `current/`，等真的产生新结论再补 ADR。

  ## 更正与推翻

  - **同日更正**：`### 更正（同日）` 挂在原条目下，不改标题
  - **跨日更正**：新条目 + 旧条目正文首行挂 `> ⚠️ 已被 YYYY-MM-DD 取代，勿用` + 索引行两端加 `~~`；旧正文留在原位不搬
  - **结论被推翻**：旧条目整块搬 `archive.md`，索引行改为 `~~已取代~~ → archive`，同时覆盖 `current/` 对应页
  - **同一件事不许追加成新条目**：只要还能确认是同一个决定，就改原条目或挂更正；连挂两次说明原条目没把决定写清楚

  ## 落盘

  追加当月正文 → 加索引行（≤100 字，带状态标记）→ 跨月时建正文与索引两个文件 → 若改变了「现在怎么配 / 怎么用」，同一次提交内覆盖 `current/` 对应页，不留「详见 current/」这类占位行 → 隔几天才补记的，标题写**当时发生**的日期，索引行末尾标「（补录）」。

  ## 读取

  - 查「有没有做过 / 当时怎么定」：`grep -n '^## ' docs/decisions/YYYY-MM.md`，或 `grep -n '关键词' docs/decisions/index/*.index.md` 先看索引行。
  - 查「现在是什么样」：只读 `docs/current/`，不要翻归档。
